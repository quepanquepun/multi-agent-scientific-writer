# Multi-Agent Scientific Writer

A multi-agent system that turns a research topic into a structured scientific document in PDF format,
with a cover page, a table of contents, sections and references. It is built with
[CrewAI](https://www.crewai.com/) and runs on a **local LLM** (Mistral-NeMo-Instruct 12B served by LM Studio).
A web interface in Streamlit takes the topic and returns the PDF.

## Pipeline

A CrewAI `Flow` chains four specialized agents:

| Stage | Agent | Tools | Output |
|---|---|---|---|
| 1 | Scientific Researcher | Web search (Serper), web scraping + LLM summarization | Document outline, key findings, references |
| 2 | Scientific Writer | Web search, web scraping | Full section content in Markdown |
| 3 | Image Specialist | Image search (Serper) | Cover image |
| 4 | Document Structurer | — | Final academic structure: abstract, sections, conclusions, references |

The final Markdown is cleaned of agent meta-comments and rendered to PDF with WeasyPrint, using an academic
layout: cover page, table of contents with internal links and page numbering.

## Requirements

- Python ≥ 3.10.
- An LLM. By default, [LM Studio](https://lmstudio.ai/) serves `mistral-nemo-instruct-2407` at
  `http://127.0.0.1:1234`. Other local models or a cloud API can be used instead
  (see [Using a different LLM](#using-a-different-llm)).
- A [Serper](https://serper.dev) API key for web and image search. A free tier is available.
- WeasyPrint system libraries (Pango). See the
  [installation guide](https://doc.courtbouillon.org/weasyprint/stable/first_steps.html).

## Usage

```bash
git clone https://github.com/quepanquepun/multi-agent-scientific-writer.git
cd multi-agent-scientific-writer
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env            # add your SERPER_API_KEY
streamlit run main.py
```

Enter a topic, click **Generate Document**, and download the PDF when it finishes.

## Using a different LLM

CrewAI accepts any provider supported by [LiteLLM](https://docs.litellm.ai/docs/providers) through a
`provider/model` string. Edit the `LLM(...)` definition in **`scientific_agents.py`**, and the one in
**`tools/browser_tools.py`** that summarizes scraped pages:

```python
# Another model in LM Studio (default setup)
LLM(model="lm_studio/<model-name>", base_url="http://127.0.0.1:1234/v1", api_key="lmstudio")

# Ollama
LLM(model="ollama/<model-name>", base_url="http://localhost:11434")

# Cloud APIs: the key is read from .env
LLM(model="openai/<model-name>")        # OPENAI_API_KEY
LLM(model="anthropic/<model-name>")     # ANTHROPIC_API_KEY
LLM(model="gemini/<model-name>")        # GEMINI_API_KEY
```

Larger models follow the formatting instructions more reliably and produce longer, better-structured documents.
